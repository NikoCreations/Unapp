Getting started

Unapp is a native macOS utility designed to analyze an application and identify files that may belong to it.

Instead of assuming that every file with a similar name belongs to the application, Unapp evaluates multiple pieces of information and assigns different evidence levels.

info

Unapp is designed around review before removal. Detected files can be inspected before the uninstall is confirmed.

Installation

Open the Unapp disk image and drag the application into your Applications folder.

/Applications/Unapp.app

Unapp 1.0 targets Apple Silicon Macs running macOS 27 or later.

First launch

The first launch may request Full Disk Access. This permission allows Unapp to inspect locations protected by macOS privacy controls.

Uninstalling an application

Start by selecting an application. Unapp reads the application's bundle information and starts an analysis.

Review the results

  • Check the application name.
  • Review the detected files.
  • Check the evidence level.
  • Confirm the items you want to remove.

Removal

Selected items are moved to the macOS Trash using the system file-management mechanism.

File detection

macOS does not provide a universal database containing every file ever created by an application. An uninstaller therefore has to determine relationships using available application metadata and filesystem evidence.

Bundle identifiers

The bundle identifier is one of the strongest identifiers available. For example:

com.example.Application

Unapp can use this identifier when evaluating preferences, containers and other application-specific paths.

Application containers

Sandboxed applications can use dedicated containers. These can provide a direct relationship between an application and its stored data.

Application names

Application names can also provide useful evidence in locations such as caches, Application Support and logs. These matches are treated differently from exact identifier matches.

Evidence levels

Detection strength matters. Unapp therefore separates files into three evidence levels.

Level Meaning Handling
EXACT Directly associated with an application identifier or declared container. Removable
STRONG Strong relationship based on path, application name or known location. Removable
POSSIBLE Potentially associated, but may be shared. Conservative
shield

Shared Group Containers are treated conservatively because more than one application can use the same container.

Full Disk Access

macOS privacy protections can prevent an application from reading certain directories. Unapp may therefore need Full Disk Access for a complete analysis.

Granting access

Open System Settings and go to Privacy & Security → Full Disk Access. Enable Unapp and launch it again.

System Settings → Privacy & Security → Full Disk Access → Unapp → Enabled
lock

macOS controls this permission. Unapp cannot grant Full Disk Access to itself.

Troubleshooting

Some files are missing

Check Full Disk Access first. macOS may prevent access to protected locations when the permission is disabled.

An application is not detected

Make sure the selected item is a valid macOS .app bundle.

A file is marked as possible

This means the available evidence does not establish a sufficiently strong relationship for automatic removal. Shared data is intentionally handled conservatively.

Can removed files be recovered?

Files moved to Trash remain subject to the normal macOS Trash workflow until the Trash is emptied.
